## 1. コード調査の結果（接続点）

| ファイル | 役割 | 本設計での扱い |
|---|---|---|
| `src/sim/fly.worker.js` | 1匹＝1 Worker。脳・物理・感覚を1ms刻みで回す | **変更しない** |
| `src/sim/fly.js` `FlyAgent` | 感覚 → 脳 → Motor → MuJoCo の閉ループ。`behavior()`で行動ラベルを返す | 変更しない |
| `src/sim/motor.js` `Motor.apply()` | 下降ニューロン(DN)の発火率を `cmd` に変換する | 変更しない（出力を読むだけ） |
| `src/arena.js` `onWorker()` | Workerから30Hzで届く`pose`メッセージを受けて描画する | **ここに接続する** |
| `src/arena.js` `buildFlyMesh()` | ハエの見た目（`visual.instantiate`）を生成する | 人型に差し替える |

Workerが30Hzで送る`pose`メッセージには、必要な情報がすべて揃っている。

- `cmd.v`：前進速度（-0.35〜1、負は後退）
- `cmd.turn`：旋回（-0.6〜0.6、正が左）
- `cmd.grooming` / `cmd.groom`：毛づくろい中かどうか／その強度
- `cmd.escape` / `cmd.takeoff`：巨大繊維(GF)と離陸系DNの発火率
- `cmd.court` / `cmd.singing`：求愛
- `behavior`：`walking`、`turning left`、`grooming`、`feeding`、`escape jump`、`taking off`、`flying…`、`standing`、`dead` などのラベル
- `pos`、`yaw`、`energy`、`health`、`flying`、`feeding`

したがって、**Worker側（脳と物理）は一切触らず、メインスレッドの描画層だけで人型化できる**。

## 2. アーキテクチャ：B1「操り人形」方式

```
[fly.worker.js]  脳 + ハエの物理ボディ（非表示のまま動き続ける）
      │ pose (30Hz): pos, yaw, cmd, behavior, energy …
      ▼
[arena.js onWorker]
      ├─► HumanoidRenderer   VRMキャラをpos/yawに置き、cmd/behaviorでアニメを選ぶ
      └─► AgentBridge        行動イベントを検出し、外部エージェント/ツールを呼ぶ（方針b）
```

ハエの物理ボディは非表示にしたまま動かし続ける。脳の感覚入力（脚先の味覚、固有受容、接触、複眼の視覚）は、このボディから生成され続ける。人型キャラはその位置と向きを受け取り、アニメーションで「演じる」。

| 比較 | B1 操り人形（採用） | B2 物理ボディ撤去 |
|---|---|---|
| Worker・脳の変更 | なし | 感覚生成を作り直す必要がある |
| 脳の閉ループ | 完全に維持される | 固有受容・脚先の味覚などが失われる |
| 見た目と当たり判定のずれ | 小さなずれがある（体の大きさ・形が違う） | なし |
| 工数 | 小 | 大 |

B2は、B1で見た目のずれが問題になった場合にのみ検討する。

### 2.1 スケール

アリーナは半径2.5cm、ハエの体長は約0.25cm（単位はcm）。人型キャラの身長を約0.3に正規化して配置する。世界全体の縮尺は変えない。

## 3. HumanoidRenderer

### 3.1 読み込み

- `@pixiv/three-vrm`でVRMを読み込む。リポジトリのThree.jsが0.186なので、互換バージョンをまず確認する
- モデルはVRoid公式サンプル（AvatarSample_A/B/C、CC0）から1体を採用する
- アニメーションはQuaternius UALのglTFを、VRMのヒューマノイドボーンにリターゲットする
  - three-vrm公式サンプルのMixamoリターゲット手法を流用する（UALはMixamo互換リグと説明されている）

### 3.2 状態機械（行動 → アニメーション）

優先度の高い順に判定する。

| 優先 | 条件（pose） | 人型の動作 | UALクリップ候補 |
|---|---|---|---|
| 1 | `alive === false` | 倒れる | Death |
| 2 | `behavior === 'escape jump'` | 飛びのく | Jump / Dodge |
| 3 | （飛行：7番により無効化しない。アバターは歩いて見せる） | — | 離陸を止めるため、`escapeJump`スキャフォールドの自発離陸を停止する。逃避ジャンプ自体は残す。停止方法はP2で確認する |
| 4 | `behavior === 'feeding'` またはproboscis系ラベル | しゃがんで食べる | Crouch / Interact_Ground |
| 5 | `cmd.grooming` | 顔や頭をこする | 該当エモート。なければ自作 |
| 6 | `cmd.v < -0.05` | 後ずさる | Walk_Back |
| 7 | `cmd.v > 0.05` | 歩く→走る（`v`でブレンド） | Walk / Jog / Sprint |
| 8 | それ以外 | 待機 | Idle |

- 旋回は`yaw`をルート回転としてそのまま使う。`cmd.turn`は上半身のひねり（見た目の補助）に使う
- 求愛（`court`、`singing`）は描画しない。脳側の求愛は、雄1体でアリーナを動かす限り発火しない
- 切り替えは`AnimationMixer`のクロスフェード（0.2秒）で行う。30Hzで届く`pos`は、既存の`prev`/`last`補間を流用する

### 3.3 ハエメッシュの扱い

`buildFlyMesh()`に表示モードの分岐を入れる（`?avatar=vrm`）。人型モードではハエのメッシュを生成しないか非表示にする。UIのクリック選択（raycast）は、人型の当たり判定用カプセルに付け替える。

## 4. AgentBridge（方針b：外部エージェント/ツール呼び出し）

### 4.1 構成

```
[ブラウザ arena.js]
  AgentBridge
    EventDetector : poseの行動ラベルの遷移や閾値からイベントを作る
    RuleTable     : イベント → 呼び出す外部エージェント/ツールの対応表（JSON）
    Client        : WebSocketでローカルのブリッジサーバへ送る
        │
        ▼
[bridge-server（Node, localhost）]
    外部エージェントの起動はすべてここで行う（ブラウザからはコマンドを実行しない）
    レート制限、呼び出しログ
    Ollama / Claude Code / Codex のいずれかを呼ぶ（4.1.1）
        │ 結果
        ▼
[ブラウザ] 吹き出し表示、音声、ログ
```

### 4.1.1 中継サーバのバックエンド（差し替え可能）

| バックエンド | 起動方法 | 向いている用途 | 応答時間の目安 | 費用 |
|---|---|---|---|---|
| **Ollama（既定）** | HTTP `POST localhost:11434/api/chat` | 高頻度の発話（セリフ・独り言） | 1秒前後（Macでの小型モデル） | 無料（ローカル実行） |
| Claude Code | `claude -p "<prompt>" --allowedTools …` | たまに行う重い処理（調べもの、ファイル生成） | 数秒〜数十秒 | サブスクリプション／APIの使用量を消費する |
| Codex | `codex exec --sandbox read-only "<prompt>"` | 同上 | 数秒〜数十秒 | 同上 |

- イベントごとに使うバックエンドを`RuleTable`で指定する。例：`startled` → Ollama、`idle_long` → Claude Code
- **安全策（Claude Code / Codex）**：ハエの行動がきっかけで自律エージェントが動くので、次を必須にする
  - 作業ディレクトリを専用フォルダに限定する
  - Claude Codeは`--allowedTools`で許可するツールを最小限にする。権限確認を省略するオプションは使わない
  - Codexは`--sandbox read-only`から始める
  - 同時に実行するのは1プロセスまで。タイムアウトは60秒
  - プロンプトに入れるのは中継サーバが組み立てた固定テンプレートとイベントJSONだけにする
- Ollamaはツール実行をしないので、上記の安全策は不要

### 4.2 エージェント端末：アリーナに置く物理オブジェクト（主となる呼び出し方）

外部エージェント（Ollama / Claude Code / Codex）を、アリーナ上に置く「端末」として表現する。ハエが端末に触れた時に、そのエージェントを呼び出す。

#### 4.2.1 コード調査で分かった前提

| 既存オブジェクト | ハエの反応 | 端末としての適性 |
|---|---|---|
| `obstacles`（箱） | 触角が触れると向きを変えて離れる（`intrinsic.js`の回避処理） | 低い。一瞬ぶつかるだけで、すぐ離れていく |
| `food`（円形パッチ） | 空腹のハエが脚や口で糖を感じると止まって食べる | **高い**。上に乗って留まる |
| `odors`（匂いの広がり） | vinegarやbananaは誘引、CO2やgeosminは忌避（`senses.js`の`ODORANTS`） | 遠くから見つけて寄ってくるための手がかりになる |

ハエに「エージェントを呼びたい」という意図は存在しない。寄ってくる理由は、匂いと空腹度（脳の状態）である。つまり「触りたい時に触る」は、**匂いに引かれ、空腹なら留まる**という形で実現する。

#### 4.2.2 端末の構成

端末1台＝次の3つの組み合わせ。`env`に`agents`配列を追加する（Workerは未知のキーを無視するので影響しない）。

```js
agents: [
  { id: 'ollama', backend: 'ollama', x: -1.2, y: 1.0, r: 0.22,
    odor: 'banana',  strength: 0.8, sigma: 0.8,   // 呼び寄せる匂い
    sugar: 0.3,                                    // 乗ると少し甘い＝留まる理由
    cooldownMs: 8000 },
  { id: 'claude', backend: 'claude-code', x: 1.3, y: -1.0, r: 0.22,
    odor: 'vinegar', strength: 0.6, sigma: 0.7, sugar: 0.3, cooldownMs: 60000 },
]
```

- 起動時に`agents`から、`food`（パッチ）と`odors`（匂い）のエントリを自動生成して`env`に追加する。脳と物理は既存の仕組みのまま反応する
- パッチの糖は減らないようにする（`amount`を毎回補充する）
- 見た目：パッチの上に端末の3Dモデル（小型のキオスク）を描画する。これは見た目だけで、当たり判定は持たせない（持たせると回避されてしまう）

#### 4.2.3 「触った」の判定

- メインスレッドで、`pose.pos`と端末の中心との距離が`r`未満の状態が300ms続いたら「接触」とする
- 接触するとイベント`touched_agent`を発行する。クールダウン中は無視する
- 端末は「呼び出し中」「応答あり」を光り方で表示し、応答は吹き出しで出す

#### 4.2.4 応答をハエに返す（閉ループ）

エージェントの応答を、ハエが感じられる刺激に変換して環境に返す。

| 応答の種類 | ハエへの返し方 | ハエ側の変化 |
|---|---|---|
| 成功・肯定的 | 端末の糖を一時的に増やす | 留まる・食べる |
| 失敗・エラー | 端末に苦味（`bitterPatches`）を一時的に出す | 離れる |
| 何かを知らせたい | 匂いを一時的に強める | 寄ってくる |

- 変換は中継サーバの結果に対するルールで決める。LLMに「肯定か否か」を1語で分類させてもよい
- 注意：現在のアリーナのハエは**学習しない**。どの端末が「良い」かを覚えて通うようにはならない。リポジトリにはキノコ体の学習（`src/mb/`、匂いと報酬の連合）の実験コードがあるが、アリーナの閉ループにはつながっていない。これを接続するのは将来の拡張とする

#### 4.2.5 確認が必要な点（実装前に検証する）

- bananaとvinegarのどちらに、どの程度強く寄っていくか（匂いによる誘引が空腹度に依存するかも含めて、既存の`scripts/run_fly.mjs`で実験して確認する）
- 端末を複数置いた時に、ハエがそれぞれを訪れる頻度

### 4.3 行動イベント（補助の呼び出し方）

| イベント | 検出条件 | 呼び出し例 |
|---|---|---|
| `startled` | `behavior`が`escape jump`に遷移 | LLMに驚きのセリフを1行生成させる |
| `hungry` | `energy < 0.3`に下がった | 空腹を訴えるセリフを生成させる |
| `found_food` | `feeding`に遷移 | 喜びのセリフを生成させる |
| `grooming` | `cmd.grooming`が1.5秒以上続いた | 独り言を生成させる |
| `idle_long` | `standing`が10秒以上続いた | 退屈そうなつぶやきを生成させる |
| `died` | `alive`がfalseに遷移 | 最期の一言を生成させる |

- 行動の決定権は常にハエ脳にある。外部エージェントは「発話・ツール実行」という出口を担う
- 1イベントあたりのクールダウン（例：10秒）と、全体のレート上限（例：毎分6回）を設ける

### 4.4 送信データ（JSON）

```json
{
  "event": "startled",
  "t_ms": 123456,
  "agent_id": 0,
  "state": { "behavior": "escape jump", "energy": 0.62, "pos": [0.4, -1.1], "yaw": 1.2, "flying": false },
  "recent_behaviors": ["walking", "turning left", "escape jump"]
}
```

### 4.5 将来の拡張（今回の範囲外）

外部から返ってきた結果を感覚入力として脳に戻す。既存の`stimulate`メッセージ（任意ニューロンへの駆動）や`env`更新（餌・匂いの配置）を使う。これで「外部の出来事にハエ脳が反応する」双方向ループになる。

## 5. 実装フェーズ

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| P0 | ローカル起動（`npm install && npm run dev`） | arena.htmlでハエが歩く |

## 6. テスト設計

| 対象 | 方法 | 合格基準 |
|---|---|---|
| 状態機械 | 純関数`selectAnim(pose)`の単体テスト。行動ラベルごとにposeを用意する | 表の優先順どおりに判定される |
| 追従 | 既存のheadless実行（`scripts/run_fly.mjs`）の軌跡と、描画した人型のルート位置を比較する | 誤差が体長の10%以内 |
| 行動の網羅 | Playwright（既存のdevDependency）で`nearodor`・`threat`プリセットを実行し、スクリーンショットを撮る | 歩行・摂食・逃避の3つのアニメが出る |
| EventDetector | 記録したposeの列を再生する | イベントが期待どおりに発火し、クールダウンが効く |
| ブリッジ | モックサーバで疎通テストを行う | APIキーがブラウザに一切露出しない |
| 性能 | ハエ1〜4体でFPSを計測する | 人型化の前と比べて低下が10%以内 |

## 7. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| three-vrmとThree.js 0.186の互換性 | P1が遅れる | 最初に最小サンプルで検証する。合わなければ対応バージョンに合わせる |
| UALからVRMへのリターゲット品質 | 動きが崩れる | 最初は歩行・待機だけで検証する。崩れる場合はVRMA形式のアニメに切り替える |
| 毛づくろいに合うクリップがない | 見た目の説得力が落ちる | 短いクリップを自作する（Blender、数秒程度） |
| 元のハエの物理ボディとのずれ | 壁際などで体が貫通して見える | 当面は許容する。問題になればB2を検討する |
| 行動がハエ由来で人間らしくない | 期待とのずれ | 仕様として受け入れる。人間らしさはAgentBridge側の発話で補う |
| LLM呼び出しのコストと遅延 | 費用、応答遅れ | クールダウン、レート上限、低価格モデルを使う |

## 8. オーナー確認事項

1. Ollamaで使うモデル（Macのメモリ量に合わせて選ぶ。日本語の発話なら7〜9Bクラスが目安）
2. Claude Code / Codex に任せたい具体的な仕事（初版では発話のみを想定し、ツール実行は後回しにする）
3. 端末の応答をハエに返すか（4.2.4の閉ループ）。返さない場合、端末は「触ると呼び出されるだけ」になる

## 9. 実装状況

### 実装済み

- `src/agents/` に再生可能な `EventDetector`、`rules.json`／`RuleTable`、再接続・バックオフ付き WebSocket `Client`、それらを接続する `AgentBridge` を追加した。接触、驚き、空腹、摂食発見、毛づくろい、長時間アイドル、死亡を検出し、イベントごとのクールダウンと全体6件／分の上限を適用する。
- `arena.js` に `?bridge=ws://…` の明示接続と、`env=agents&avatar=vrm` の自動接続を追加した。端末の idle／calling／replied／error 表示、VRMの頭上（`humanoid.root` のワールド位置＋固定高さ）または通常のハエ上の吹き出しを実装した。
- `?touch=debug` では端末ごとに `call now (synthetic)` ボタンを表示する。合成イベントも `EventDetector` から `Client` へ流れ、リクエストIDだけ `debug-` 接頭辞にするため、イベントpayloadにデバッグ用フィールドは追加していない。
- 応答の `valence` を `syncEnv()` に接続した。`positive` は端末の糖、`negative` は `bitterPatches`、`notify` は端末の匂いを約10秒だけ強め、期限後に元へ戻す。
- root の `npm run bridge`／`npm run bridge:mock` を追加した。bridge の成功ログには検証済みイベントpayloadも保存するようにした。
- `tests/event-detector.test.js` と replay fixture、Playwrightの `tests/agent-e2e.mjs` を追加した。

### 差異・未解決

- `touched_agent` では既存bridge-serverの任意フィールド `terminal_id` を使って端末と応答刺激を対応付ける。合成イベントを示す新しいpayloadフィールドは追加していない。
- Claude Code／Codexはブラウザ側の端末ルーティングまで実装したが、費用を避けるためライブ呼び出しは実行していない。Ollamaは実モデルで一度疎通確認した。
- `scripts/check_humanoid.mjs` は既存の `heading must track raw yaw` で失敗した。レビュー中の `src/humanoid/*` を変更しない制約のため、このターンでは修正していない。
- 自然な端末訪問はP3測定どおり弱いため、E2Eでは許可された `?touch=debug` の合成接触を使った。

### 実行方法

```sh
npm install
npm run dev
npm run bridge:mock
# http://127.0.0.1:5173/arena.html?env=agents&avatar=vrm&bridge=ws://127.0.0.1:8787&touch=debug
```

Ollamaの実接続は `node bridge-server/scripts/smoke-ollama.mjs`、ブラウザE2Eは `node tests/agent-e2e.mjs` で実行できる。
